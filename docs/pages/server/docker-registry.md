# Docker Registry

Self-hosted Docker image registry with HTTPS support, working with or without Kubernetes (k3s).

## Overview

This module provides a Docker registry service that:
- Runs a Docker Registry (compatible with Docker Engine)
- Generates a self-signed TLS certificate with a proper SAN (Subject Alternative Name)
- Exposes the registry over HTTPS via **Traefik** (when k3s is enabled) or **nginx** (fallback, no k3s)
- Supports unlimited image sizes and long-running push/pull operations

## Architecture

### With k3s (Traefik)

```
┌─────────────────────────────────────────────────────┐
│                    Client                            │
│          (docker push/pull registry.home)            │
└──────────────────┬────────────────────────────────────┘
                    │ HTTPS (port 443)
                    ▼
┌──────────────────────────────────────────────────────┐
│                  Traefik (k3s)                        │
│   - Secret: registry-home-tls (cert + key)            │
│   - TLSStore: default cert for k3s namespace          │
│   - IngressRoute: routes Host(registry.home)          │
│   - Service: ClusterIP docker-registry-svc            │
│   - Endpoints: points to host IP (auto-detected)      │
└──────────────────┬────────────────────────────────────┘
                    │ HTTP (port 5000)
                    ▼
┌──────────────────────────────────────────────────────┐
│              Docker Registry (NixOS)                  │
│   - Data: /home/docker-registry/data                  │
│   - Listens on: 0.0.0.0:5000                          │
└──────────────────────────────────────────────────────┘
```

Traefik does not support `ExternalName` services, so the registry is exposed to the
k3s cluster via a `ClusterIP` Service backed by a manually managed `Endpoints`
object pointing at the host's IP address (auto-detected at apply time, no
hardcoded IP).

### Without k3s (nginx)

```
┌─────────────────────────────────────────────────────┐
│                    Client                            │
│          (docker push/pull registry.home)            │
└──────────────────┬────────────────────────────────────┘
                    │ HTTPS (port 443)
                    ▼
┌──────────────────────────────────────────────────────┐
│                  nginx                                │
│   - TLS termination (registry.home.crt/key)           │
│   - reverse_proxy → localhost:5000                    │
└──────────────────┬────────────────────────────────────┘
                    │ HTTP (port 5000)
                    ▼
┌──────────────────────────────────────────────────────┐
│              Docker Registry (NixOS)                  │
└──────────────────────────────────────────────────────┘
```

The Traefik integration (`traefik.nix`) is enabled only when `services.k3s.enable`
is true; the nginx integration (`nginx.nix`) is enabled only when it is false.
Both share the same certificate generated by `certificates/default.nix`.

## Components

`server/docker-registry/`:

| File | Purpose |
|------|---------|
| `default.nix` | Module composition and `/etc/hosts` entry for `registry.home` |
| `registry.nix` | Docker Registry service configuration |
| `certificates/default.nix` | Self-signed certificate generation and system trust |
| `certificates/traefik.nix` | k3s/Traefik integration (enabled when k3s is on) |
| `certificates/nginx.nix` | nginx integration (enabled when k3s is off) |
| `certificates/registry.yaml` | Traefik manifests: Namespace, TLSStore, IngressRoute, Service, Endpoints |
| `certificates/secret.yaml` | Kubernetes Secret template for the TLS cert/key |
| `certificates/scripts/wait-for-k8s.sh` | Waits for the k3s API server to be ready |
| `certificates/scripts/update-traefik-secret.sh` | Base64-encodes cert/key and applies the Secret |
| `certificates/scripts/apply-registry-manifests.sh` | Detects host IP and applies `registry.yaml` |

### `certificates/default.nix`

Generates a self-signed TLS certificate with a proper SAN via an OpenSSL config
file (not command-line `-addext`, which some clients reject):
- CN: `registry.home`
- SAN: `DNS:registry.home`
- Validity: 365 days
- Key: RSA 4096-bit

The certificate is copied to `/var/lib/registry-certs/` by the
`setup-registry-cert` systemd service and trusted system-wide via
`security.pki.certificateFiles`.

### `registry.nix`

Docker Registry service configuration:
- Enabled by default, starts on boot
- Data directory: `/home/docker-registry/data`
- Listens on `0.0.0.0:5000` (reachable from the k3s network, not just localhost)
- Features: image deletion enabled, storage redirect disabled, storage-driver
  health checks, JSON logging
- Resource limits: `MemoryMax=512M`, `MemoryHigh=400M`, `CPUQuota=200%`, `IOWeight=500`
- A separate `docker-registry-health` systemd service polls `http://localhost:5000/v2/`

### `certificates/traefik.nix`

Only active when `services.k3s.enable` is true. Defines two oneshot systemd
services, run in order:

1. **`update-traefik-registry-secret`** — waits for k3s, then runs
   `update-traefik-secret.sh`, which reads the cert/key from `CERT_DIR`,
   base64-encodes them, substitutes them into `secret.yaml`, and applies it
   with `kubectl`.
2. **`apply-registry-manifests`** — runs `apply-registry-manifests.sh`, which
   detects the host IP (`hostname -I`, falling back to `ip addr show`),
   substitutes it for `HOST_IP_PLACEHOLDER` in `registry.yaml`, and applies
   the manifest with `kubectl`.

Both scripts include `[INFO]`/`[DEBUG]`/`[ERROR]` logging and validate their
substitutions before applying anything.

### `certificates/nginx.nix`

Only active when `services.k3s.enable` is false. Configures nginx as a TLS
terminating reverse proxy for `registry.home`, forwarding to
`http://localhost:5000`.

## Usage

### Push an image to registry

```bash
# Tag image with registry hostname
docker tag myapp:latest registry.home/myapp:latest

# Push to registry
docker push registry.home/myapp:latest
```

### Pull an image from registry

```bash
docker pull registry.home/myapp:latest
```

### List images in registry

```bash
curl -k https://registry.home/v2/_catalog
```

### Delete an image

```bash
curl -k -X DELETE https://registry.home/v2/myapp/manifests/sha256:<digest>
```

## Environment Setup

### k3s Integration

The registry is integrated with k3s as a mirror in `server/k8s/registry.nix`:

```yaml
mirrors:
  registry.home:
    endpoint:
      - https://registry.home
configs:
  registry.home:
    tls:
      ca_file: /var/lib/registry-certs/registry.home.crt
```

This allows k3s to pull images from the registry with certificate validation.

### System Hosts Entry

`/etc/hosts` entry is configured by `default.nix`:

```
127.0.0.1    registry.home
```

## Certificate Management

### Automatic Generation

Certificates are generated during system build as a Nix derivation, ensuring
reproducibility and consistency across system rebuilds.

### Manual Regeneration

To regenerate the certificate and re-sync the Traefik Secret after a system
rebuild:

```bash
sudo systemctl restart setup-registry-cert.service
kubectl delete secret registry-home-tls -n kube-system
sudo systemctl restart update-traefik-registry-secret.service
```

### Viewing Certificate Details

```bash
openssl x509 -in /var/lib/registry-certs/registry.home.crt -text -noout
```

## Networking

### Firewall

- With k3s: Traefik handles HTTPS on port 443.
- Without k3s: nginx handles HTTPS on port 443.
- The Docker Registry API itself listens on `0.0.0.0:5000` so it is reachable
  from the k3s network, but is not directly exposed outside the host firewall.

### DNS Resolution

- `registry.home` resolves to `127.0.0.1` via `/etc/hosts`
- The TLS certificate is valid for `registry.home`

## Troubleshooting

### Certificate validation errors

Ensure the certificate is properly trusted:

```bash
trust list | grep registry.home
```

### Registry not accessible from k3s / Traefik

```bash
kubectl get ingressroute -A | grep registry
kubectl describe ingressroute registry-home -n kube-system
kubectl get endpoints docker-registry-svc -n kube-system -o yaml
```

If the `Endpoints` object has an empty or wrong IP, restart
`apply-registry-manifests.service` and check its logs — it re-detects the
host IP each run.

### Images not accessible from k3s

```bash
cat /etc/rancher/k3s/registries.yaml
```

### Health check service failing

```bash
systemctl status docker-registry-health
journalctl -u docker-registry-health -n 20
curl -f http://localhost:5000/v2/ && echo "Health OK" || echo "Health FAILED"
```

### Out of memory errors

```bash
systemctl show docker-registry --property MemoryMax
systemctl show docker-registry --property MemoryHigh
watch -n 1 'systemctl show docker-registry --property MemoryCurrent'
```

Increase `MemoryMax`/`MemoryHigh` in `registry.nix` if needed.

## Security Considerations

### Self-signed Certificate

This registry uses a self-signed certificate. For production use, consider:
- Using Let's Encrypt via cert-manager
- Using a proper CA certificate
- Ensuring all clients trust the certificate

### Access Control

Currently, the registry has no authentication. Consider:
- Adding Traefik basic auth or nginx `auth_basic`
- Using a reverse proxy with OAuth2
- Running the registry in a private network only
